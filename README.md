# ZeroCAD

Параметрический CAD-сервер на **чистом Rust (ноль зависимостей)**. Сервер строит
меш и STL, браузер только рисует (Three.js-«плеер» в духе Printables).

```
src/main.rs      — HTTP-сервер на std::net (роуты /, /api/wheel.stl)
src/geometry.rs  — меш колеса: 2D-контур с V-карманами -> экструзия
src/stl.rs       — бинарный и ASCII STL
web/index.html   — вьюер (вшивается в бинарник через include_str!)
```

Запуск:

```bash
cargo run
```

→ `http://127.0.0.1:8777` — ползунки дёргают Rust на каждое движение
(генерация ~3 мс, 5760 треугольников), кнопка отдаёт готовый `wheel.stl` в слайсер.

Параметры API: `GET /api/wheel.stl?dia=70&thk=11&shaft=5&n=12&depth=6&mouth=11`
(мм/штуки/градусы; ответ — binary STL + заголовки `X-Apex-Mm`, `X-Pitch-Mm`, `X-Gen-Us`).

Следующая ступень лесенки (см. §3): обёртка над `csgrs` для настоящих булевых.

## 0. Кто пользователь и что он хочет (важно для тона)

- Пишет на **Rust**, любит **свои инструменты без зависимостей** (уже есть проект
  `immo_off_hitachi` — чистый Rust, ноль крейтов).
- Мыслит как инженер-практик: «сделаем из говна и палок первый прототип», растит
  сложность постепенно (сам приводил пример: игру делали сначала «из квадратов как
  Minecraft», потом «из треугольников» — за ~4 часа).
- Хочет **понимать, как всё устроено**, а не получить чёрный ящик.
- Предпочитает **бесплатное** и **конкретные рабочие результаты**, а не лекции.
- Отвечать по-русски.

### Прикладная задача (откуда всё пошло)
Пользователь строит **механизм-дозатор арахиса** (выдаёт орехи поштучно):
вращающееся **колесо с V-образными карманами по ребру** + неподвижный кожух +
скребок + ИК-датчик прерывания луча для подсчёта + мотор. Нужна **3D-модель этого
колеса для печати**. Отсюда весь разговор про CAD/код/STL.

Параметры колеса выведены из статьи MDPI `10.3390/app16021008` (метрология
высевающих аппаратов, V-скребок):
- ширина устья кармана: `W_max ≤ V_W < 1.2·W_max`
- глубина: `¼·T_max ≤ V_D < ⅔·T_max`
- длина/раскрыв: `½·L_max ≤ V_L < L_max`
- угол V ≈ **112°**, наклон стенки 3–5°
- где L/W/T — длина/ширина/толщина ореха (пользователь ещё должен **замерить реальный арахис**).
- **толщина колеса ≈ ширина ореха** (чтобы орех ложился поперёк).

Рабочие дефолты (в вьюере): Ø70 мм, толщина 11 мм, вал 5 мм, 12 карманов,
глубина 6 мм, устье 11°. Это стартовая точка, финал — после замеров ореха.

## 1. Готовые программы для 3D (что рассматривали)

| Программа | Бесплатно | Точность под печатную шестерёнку | Я («агент») рисую сам через MCP |
|---|---|---|---|
| **Autodesk Fusion** ⭐ | ✅ лицензия **Personal** (некоммерч.) | 🟢 инженерная, параметрика | ✅ **официальный** Fusion **MCP-сервер** |
| **Blender** + BlenderMCP | ✅ | 🟡 меш/художественная, для точной механики слабо | ✅ но сторонний аддон+сервер |
| **SketchUp** (быв. Google) | ✅ SketchUp **Free** (веб) | 🔴 для архитектуры/мебели, кривые грубые | ❌ |
| **FreeCAD** | ✅ | 🟢 параметрика (ядро OCCT) | ❌ (но есть FreeCAD-MCP, сырой) |
| **OpenSCAD** | ✅ | 🟢 code-CAD, точно | ❌ (я пишу код) |

### Ключевой факт про MCP («чтобы агент рисовал сам»)
- **MCP-сервер** = способ дать агенту инструменты внутри программы. Пользователь
  видел видео, где человек через **Fusion MCP** заставляет Claude моделировать штамп
  прямо во Fusion (сам «руками ничего не трогает»).
- Настройка Fusion MCP: Preferences → General → включить галки **«Fusion MCP server»**
  и **«Developer tools»**; затем в Claude: Customize → Connectors → добавить
  **«Autodesk Fusion»**. **После подключения нужен перезапуск сессии Claude Code**,
  иначе инструменты не подхватятся.
- В **этой** прошлой сессии никакой CAD-MCP подключён НЕ был (реестр коннекторов пуст
  по запросам blender/cad/freecad). Поэтому «вживую рисовать во Fusion» пока нельзя —
  нужна разовая настройка пользователем + рестарт.
- Предупреждение из того же видео: модель **Fable дорогая** (43% лимита за 2 дня на
  один штамп). Практика: **Fable пишет ТЗ/промпт, а моделирует Opus**. И главное —
  «идея детали должна быть в голове у человека», нейронка не спроектирует то, чего
  автор сам не понимает.

**Рекомендация по готовым программам:** для точной печатной детали — **Fusion Personal
+ MCP** (бесплатно, инженерная точность, агент рисует сам). SketchUp — мимо (грубые
кривые). Blender — мимо для механики.

## 2. Свой код вместо программы (выбранное направление)

Пользователю ближе **написать своё** на Rust. Разложили по слоям сложности:

- **Слой 1 — экспорт STL: тривиально.** STL = просто список треугольников
  (нормаль + 3 вершины). Кто умеет строить меш из треугольников (а он умеет из игры) —
  уже умеет 90% STL-экспортёра. ASCII-формат:
  ```
  facet normal nx ny nz
    outer loop
      vertex x y z   (×3)
    endloop
  endfacet
  ```
- **Слой 2 — примитивы: легко** (часы). Куб, призма, пирамида, экструзия плоского
  контура на высоту — чистая тригонометрия + вершины.
- **Слой 3 — булевы операции: вот это тяжело.** Difference/union/intersection над
  сетками, точные кривые (NURBS), параметрические связи — за это Autodesk и берёт
  деньги. Робастно с нуля — месяцы, и всё равно глючит.

### Хитрость: для НАШЕГО колеса слой 3 НЕ нужен
Колесо строится **без 3D-булевых**: берём 2D-контур (окружность с V-вырезами по
периметру + отверстие в центре) → **экструдируем на толщину**. Всё — линии, углы,
треугольники. Это уже реализовано (см. раздел 4).

## 3. CAD-ядра, которые можно ОБЕРНУТЬ (когда понадобятся булевы)

Идея пользователя (верная): не писать ядро, а сделать **тонкую обёртку** над готовым.

**Через FFI (C/C++ ядра):**
| Ядро | Лиц. | Что умеет | Rust-обёртка |
|---|---|---|---|
| **OpenCASCADE (OCCT)** | LGPL 🆓 | Полный **B-rep**: булевы, фаски, NURBS, STEP/IGES. Основа FreeCAD. | `opencascade-rs` (живой, местами сырой) |
| **Manifold** (Google) | MIT 🆓 | Быстрые **робастные булевы над мешами**, идеально под печать. | `manifold3d` |
| **CGAL** | GPL/платно | Nef-полиэдры, мощная геометрия. Основа булевых в OpenSCAD. | C++ FFI |
| **libfive** | MPL 🆓 | **F-rep** (функции, не грани), гладкое масштабирование. | биндинги есть |

**Чисто-Rust ядра (пользователю зайдёт больше всего):**
| Крейт | Что это |
|---|---|
| **`truck`** | Настоящее **B-rep/NURBS CAD-ядро целиком на Rust**. Молодое, но рабочее. |
| **`fornjot`** | Проект code-CAD на Rust (модель = код). Своё ядро. |
| **`csgrs`** | Готовый **CSG** (union/difference/intersection) над мешами + экспорт STL. Самый простой вход. |

### Лесенка роста (рекомендуемый маршрут)
1. **Сейчас:** сам генерю треугольники (2D-контур → экструзия). Колесу хватает. ✅ сделано
2. **Далее:** обёртка над **`csgrs`** → настоящие булевы, косые срезы, вычитания. (~пара дней)
3. **Потом:** **`manifold3d`** для скорости/надёжности на сложных мешах.
4. **Серьёзно:** **OCCT (`opencascade-rs`)** или **`truck`** → «почти Fusion»: STEP, фаски, NURBS.

## 4. Что уже РАБОТАЕТ (артефакт в этой папке)

**`wheel_viewer.html`** — самодостаточный HTML (~250 строк), **параметрический вьюер
колеса прямо в браузере**. Отвечает на вопрос «сможем ли сделать плеер как на
Printables/Thingiverse»: **да, легко**.

- **Технология:** **Three.js** (WebGL поверх `<canvas>`) с CDN cdnjs. Вся геометрия,
  вращение и экспорт STL считаются **в браузере**. Сервер нужен только чтобы отдать
  файл (можно и вовсе открыть локально).
- **Умеет:**
  - вращать деталь (ЛКМ), зум (колесо), сдвиг (ПКМ);
  - **ползунки** параметров (диаметр, толщина, вал, число карманов, глубина, ширина
    устья) — модель **пересобирается на лету**;
  - **кнопка «Скачать STL»** → `wheel.stl` (ASCII STL, генерится из меша Three.js);
  - показывает оси X/Y/Z и расчёт (радиус апекса, шаг между карманами, число треугольников).
- **Геометрия:** `THREE.Shape` (окружность, где в секторах каждого кармана радиус
  «ныряет» V-образно к апексу) + отверстие-`Path` под вал → `THREE.ExtrudeGeometry`
  на толщину. Без 3D-булевых.

### Как запустить (для следующего агента)

затем открыть `http://localhost:8777/wheel_viewer.html`.
(В прошлой сессии запускалось через `.claude/launch.json` с этим же python-сервером.)
